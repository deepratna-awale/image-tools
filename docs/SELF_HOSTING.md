# Self-hosting Image Tools

Run the whole site on your own computer or server. Everything works on the CPU with no
accounts or paid APIs; a RunPod GPU endpoint is optional and only makes the AI tools faster
(and unlocks the two tools that need it).

## Quick start

```bash
git clone https://github.com/deepratna-awale/image-tools.git
cd image-tools
./deploy/local/setup.sh
```

Then open http://localhost:3000.

The script checks Docker is running, writes `.env` with a random RabbitMQ password and an
admin token the first time, builds the images, starts the stack and waits until the site
answers. The first build downloads about 2 GB of models and takes 10 to 20 minutes; later
runs reuse the cached layers.

Prefer doing it by hand? It's the same as:

```bash
cp .env.example .env          # set RABBITMQ_DEFAULT_PASS to anything long and random
docker compose up -d --build
```

On Windows, run either from WSL 2 (Docker Desktop's default backend) or Git Bash.

## What you need

| | Minimum | Comfortable |
| --- | --- | --- |
| Docker | Docker Desktop, or Docker Engine with the Compose v2 plugin | |
| CPU | 2 cores, x86-64 or ARM64 (Apple Silicon, Graviton, Ampere all work) | 4+ cores |
| Memory | 4 GB free for Docker | 8 GB (AI Shield's High strength and the upscaler use the most) |
| Disk | 12 GB (backend image ~5.5 GB, frontend ~0.3 GB, build cache) | 20 GB |
| Network | Only for the first build (PyPI, npm, Hugging Face, GitHub releases) | |

On Docker Desktop, check **Settings → Resources** gives Docker at least 4 GB of memory.

## What runs where

`docker compose` starts four containers:

| Service | What it does | Port |
| --- | --- | --- |
| `frontend` | Next.js site; proxies every API call to `api` server-side | `FRONTEND_PORT` (3000), all interfaces |
| `api` | FastAPI: takes uploads, queues jobs, serves results | `127.0.0.1:8000` only |
| `worker` | Runs the jobs (one at a time on CPU) | none |
| `rabbitmq` | Job queue | none |

The `api` and `worker` share uploads, results and job status through the `storage` volume.

Which tools need what:

| Tool | Runs on | CPU-only time (1 MP photo, 4-core x86) |
| --- | --- | --- |
| Resize/Convert, Passport Photo, Watermark & Text, Images to PDF, Remove Metadata, Prompt Reader | Your browser | instant |
| Background Remover, Background Changer, Blur Background | Worker (CPU or GPU) | ~20 s with `bria-rmbg`, ~1 s with `isnet-general-use` |
| Sky Swap | Worker (CPU or GPU) | a few seconds |
| Image Upscaler | Worker (CPU or GPU) | about a minute per megapixel per core; CPU input capped at 1 MP |
| AI Shield | Worker (CPU or GPU) | minutes (roughly 2.5 / 5 / 14 min for Low / Medium / High on 2 cores) |
| Watermark Remover, Outpainting | **GPU endpoint only** (FLUX.1 Kontext) | not available; jobs fail with "busy, try again" |

## Configuration

Everything lives in `.env` at the repo root, which every backend container reads.
[`.env.example`](../.env.example) lists every option with comments; the ones you are most
likely to touch:

| Variable | Default | What it does |
| --- | --- | --- |
| `RABBITMQ_DEFAULT_USER` / `RABBITMQ_DEFAULT_PASS` | `imagetools` / *(required)* | Queue credentials, shared by all services |
| `FRONTEND_PORT` | `3000` | Port the site is published on |
| `API_PORT` | `8000` | Port for the API on `127.0.0.1` |
| `MAX_FILE_SIZE` | `10485760` (10 MB) | Largest upload, in bytes |
| `FILE_RETENTION_HOURS` | `24` | Uploads and results are deleted after this |
| `WORKER_CONCURRENCY` | `1` | Jobs at once; keep 1 on CPU, ~4 with a GPU |
| `REMBG_MODEL` | `bria-rmbg` | Cutout model, baked in at build time ([Models](#models)) |
| `SKY_MODEL_URL` | SegFormer-b0 | Sky segmentation model, baked in at build time |
| `RUNPOD_API_KEY` / `RUNPOD_ENDPOINT_ID` | *(empty)* | Turn on the GPU endpoint ([below](#optional-gpu-runpod-serverless)) |
| `GPU_MONTHLY_BUDGET_USD` | `10` | Estimated GPU spend per month before jobs go back to the CPU; `0` = no cap |
| `ADMIN_TOKEN` | *(generated by the script)* | Unlocks creating and revoking API keys on `/api-keys` |
| `STORAGE_TYPE` | `local` | `s3` to keep files in a bucket (`S3_BUCKET_NAME`, AWS credentials) |
| `LOG_LEVEL` | `INFO` | |

After editing `.env`, apply it with `docker compose up -d` (add `--build` if you changed a model).
Every backend setting with its default is in [`backend/config/settings.py`](../backend/config/settings.py);
any of them can be set in `.env` by its name in capitals.

## Models

The backend image downloads these at build time
([`backend/deployment/fetch_models.py`](../backend/deployment/fetch_models.py)), so the
containers need no internet afterwards:

| Used by | Model | Size | Licence |
| --- | --- | --- | --- |
| Background Remover / Changer / Blur | BRIA RMBG 2.0 (`bria-rmbg`, via rembg) | ~1 GB | CC BY-NC 4.0 (non-commercial) |
| Sky Swap | SegFormer-b0 ADE20K (ONNX) | ~15 MB | NVIDIA non-commercial |
| AI Shield | SD 1.x/2.x VAE (`sd-vae-ft-mse`) and SDXL VAE | ~2 × 330 MB | MIT |
| Upscaler | Real-ESRGAN x4plus and x4plus anime 6B | ~85 MB | BSD-3-Clause |
| Upscaler (photo vs. anime picker) | open_clip ViT-B-32 (LAION-400M) | ~350 MB | MIT |

The GPU image adds Florence-2 (MIT) and FLUX.1 Kontext [dev] (non-commercial) for the
Watermark Remover and Outpainting; `WATERMARK_FILL_MODEL=sdxl` builds it with SDXL
Inpainting (OpenRAIL++) instead.

**Running it commercially?** Swap the two non-commercial CPU models, then rebuild:

```env
REMBG_MODEL=isnet-general-use        # or birefnet-general (slower, better edges)
SKY_MODEL_URL=https://.../your-ade20k-segmentation.onnx
```

`REMBG_MODEL` accepts any [rembg model name](https://github.com/danielgatis/rembg#models).
`isnet-general-use` is also about 20× faster on CPU than `bria-rmbg`, which is worth it on
small machines even for personal use.

## Optional GPU (RunPod Serverless)

With a GPU endpoint, the worker hands model work to [RunPod Serverless](https://www.runpod.io/serverless-gpu),
which bills per second while a job runs and scales to zero when idle. Background removal
drops to ~3 s, and the Watermark Remover and Outpainting start working. If the endpoint
fails, times out or the monthly budget runs out, jobs run on your CPU instead (except those two tools).

1. Create a RunPod Serverless endpoint from the public image
   `ghcr.io/deepratna-awale/image-tools-gpu:latest`, on a 24 GB GPU, min 0 / max 3 workers,
   idle timeout 5 s, execution timeout 900 s. Step-by-step:
   [`backend/deployment/gpu/README.md`](../backend/deployment/gpu/README.md).
2. Add to `.env`:

   ```env
   RUNPOD_API_KEY=...
   RUNPOD_ENDPOINT_ID=...
   WORKER_CONCURRENCY=4
   ```

3. `docker compose up -d worker`. The worker log says `Sending model work to GPU endpoint ...`.

The first job after the endpoint has been idle waits for a cold start (about a minute).
Remove the two `RUNPOD_` lines to go back to CPU only.

## Using the API locally

The API (interactive docs at http://localhost:8000/docs) listens on `127.0.0.1:8000`.
Requests made straight to it don't need an API key; keys and rate limits only apply to
requests coming through the public HTTPS proxy ([docs/API.md](./API.md)).

```bash
API=http://localhost:8000/api/v1/background-removal
JOB=$(curl -s -F "file=@photo.jpg" $API/process | jq -r .job_id)
curl -s $API/status/$JOB                      # repeat until "completed"
curl -s $API/result/$JOB -o cutout.png
```

## Day-to-day commands

```bash
docker compose ps                    # what's running
docker compose logs -f worker        # watch jobs
docker compose restart worker        # after changing GPU settings
docker compose down                  # stop (uploads and the queue are kept in volumes)
docker compose down -v               # stop and delete all stored files and API keys

git pull && ./deploy/local/setup.sh  # update to the latest version
docker image prune -f                # reclaim space from old builds
```

## Putting it on the internet

`docker-compose.https.yml` adds Caddy with automatic HTTPS and the public API route. Point a
domain at the server, set `SITE_ADDRESS=your.domain` in `.env`, open ports 80 and 443, then:

```bash
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

For a free server, [deploy/oracle/README.md](../deploy/oracle/README.md) does all of this on
an Oracle Cloud Always Free VM with one script. This is how imagetools.top runs.

## Developing without Docker

Needs Python 3.11+, Node.js 18+ with pnpm, and RabbitMQ
(`docker run -d -p 5672:5672 rabbitmq:3-alpine` is the easiest way to get one).

```bash
# Once: Python packages and models (into ~/.u2net, or U2NET_HOME)
cd backend && python -m venv .venv && source .venv/bin/activate
pip install -r requirements/dev.txt
python deployment/fetch_models.py

# API (reloads on change), worker and frontend, each in its own terminal
cd backend && ./start.sh
cd backend && ./start-worker.sh
cd frontend && cp .env.example .env.local && pnpm install && pnpm dev
```

Site at http://localhost:3000, API docs at http://localhost:8000/docs. Tests:
`cd backend && python -m pytest tests/` and `cd frontend && pnpm lint && pnpm build`.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| The API never becomes healthy, or the worker logs RabbitMQ connection errors | Check `.env` has `RABBITMQ_DEFAULT_PASS`. Run `./deploy/local/setup.sh`, or set it by hand and `docker compose up -d`. If you changed the password after the first start, run `docker compose down -v` (RabbitMQ keeps the first one). |
| Build fails downloading a model | The build needs huggingface.co and github.com. Retry; behind a proxy, pass it to Docker's build settings. |
| Build is killed or the worker exits with code 137 | Docker ran out of memory. Give it more (Docker Desktop → Settings → Resources), or use `REMBG_MODEL=isnet-general-use`. |
| Port 3000 or 8000 already in use | Set `FRONTEND_PORT` / `API_PORT` in `.env` and `docker compose up -d`. |
| Jobs sit at "queued" | `docker compose logs worker`. A CPU job can take minutes (see [What runs where](#what-runs-where)), and jobs run one at a time. |
| Watermark Remover / Outpainting say "busy, try again" | They need the [GPU endpoint](#optional-gpu-runpod-serverless). |
| `/api-keys` asks for a token | It's `ADMIN_TOKEN` in `.env` (`grep ADMIN_TOKEN .env`). |
